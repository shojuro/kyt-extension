# Embedding Validation Guide

## Purpose

This guide explains how to validate that synthetic embeddings used in tests accurately model real production embedding behavior.

## The Problem

Our test suite (Batch 2 + Batch 7) uses **synthetic embeddings** generated by the `genEmb()` function. These embeddings are mathematically controlled to have specific distance distributions.

**This is a valid testing approach IF and ONLY IF:**
- Real embeddings from your production API have similar distance distributions
- The assumption that "synthetic ≈ real" holds true

## The Solution

The `validate_embedding_realism.js` script compares real production embeddings to synthetic test embeddings and verifies they match within an acceptable tolerance (20%).

## Running the Validation

### Quick Start

```bash
node validate_embedding_realism.js
```

### What It Does

1. **Generates real embeddings** for sample messages from both ICPs:
   - Developer ICP: Technical messages (Redis, projects, etc.)
   - Companion ICP: Emotional messages (anxiety, relationships, etc.)

2. **Generates synthetic embeddings** using the same `genEmb()` function as tests

3. **Compares distance distributions**:
   - Calculates mean and standard deviation
   - Reports percentage difference
   - **Pass threshold**: ≤20% difference

4. **Outputs verdict**:
   - ✅ PASS: Synthetic embeddings are valid proxies for production
   - ❌ FAIL: Adjustments needed to `genEmb()` function

## What to Do After Validation

### If Validation PASSES ✅

1. **Proceed with confidence**:
   - Your 100-scenario test results are valid
   - MMR algorithm is validated for production
   - Beta deployment is safe (from algorithm perspective)

2. **Document the validation**:
   - Keep validation output in `EMBEDDING_VALIDATION_REPORT.md`
   - Include in deployment documentation

3. **Optional: Create integration test** (Phase 3):
   - Small test with 10 real production scenarios
   - Run periodically to catch embedding model changes

### If Validation FAILS ❌

1. **Adjust `genEmb()` function**:
   - Located in `generate_batch2_query_complexity.js` and `generate_batch7_cross_platform.js`
   - Modify relevance/diversity multipliers to match real distributions
   - Focus on the ICP that failed (Developer or Companion)

2. **Re-generate scenarios**:
   ```bash
   node generate_batch2_query_complexity.js
   node generate_batch7_cross_platform.js
   ```

3. **Re-run tests**:
   ```bash
   node test_batch2_query_complexity.js
   node test_batch7_cross_platform.js
   ```

4. **Re-run validation**:
   ```bash
   node validate_embedding_realism.js
   ```

5. **Repeat until validation passes**

## Troubleshooting

### Error: "OPENAI_API_KEY environment variable not set"

**Solution:**
```bash
# Make sure .env file exists and has your key
cat .env  # Should show: OPENAI_API_KEY=sk-...

# If missing, copy from example and edit
cp .env.example .env
nano .env
```

### Error: "OpenAI API error: 401 Unauthorized"

**Solution:**
- Your API key is invalid or expired
- Get a new key from https://platform.openai.com/api-keys
- Update `.env` file

### Error: "Validation failed: fetch is not defined"

**Solution:**
- Update Node.js to version 18+ (includes native fetch)
- Or install a fetch polyfill: `npm install node-fetch`

### Results show >50% difference

**This is expected if:**
- You're using a different embedding model than assumed
- Your production embeddings are from a different provider
- The sample messages don't match your actual use cases

**Solution:**
- Update `DEVELOPER_MESSAGES` and `COMPANION_MESSAGES` in `validate_embedding_realism.js`
- Use actual messages from your production database
- Adjust `genEmb()` to match your specific embedding characteristics

## FAQ

**Q: Do I need to run this validation every time I run tests?**

No. Run it once to validate the assumption, then periodically (e.g., before major releases or if embedding model changes).

**Q: What if my embedding model changes?**

Re-run validation. If a different model produces different distance distributions, you'll need to adjust `genEmb()` and re-test.

**Q: Can I use a different embedding model than OpenAI?**

Yes. The validation script supports:
- OpenAI (recommended, currently supported)
- Supabase (if you have Edge Function set up)
- Anthropic (placeholder for future compatibility)

**Q: Why 20% tolerance?**

This is a pragmatic threshold:
- Embeddings have inherent variance
- 20% difference in distance still maintains relative ranking
- Tighter tolerance (e.g., 10%) may be too strict
- Looser tolerance (e.g., 30%) may miss significant divergence

**Q: Should I commit .env to git?**

**NO!** The `.env` file is already in `.gitignore`. Only commit `.env.example` with placeholder values.

## Summary

This validation process answers the critical question:

> **"Do synthetic embeddings used in tests accurately model real production behavior?"**

- ✅ **If YES**: Test results are trustworthy, proceed with confidence
- ❌ **If NO**: Adjust synthetic embeddings to match reality, re-test

This is **NOT about whether MMR works** (it does - that's mathematically proven).

This is about **whether your tests accurately predict production performance**.

Run the validation, interpret the results, and proceed accordingly.
