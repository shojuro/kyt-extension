## ✅ Recency-Aware Contradiction Resolution (2026-02-17)

### Problem: Newer Corrections Ignored
When user stores "Jerry is my best friend" and later stores "Jerry is not real — he was a test," searching for "Jerry" returns the older, semantically richer memory. Same for "I like shrimp" → "I don't like shrimp." The system had no mechanism to recognize that newer statements supersede older ones about the same entity.

### Root Causes
- Gravity scoring (temporal decay) existed on edge path but was lost after Jina reranking
- `src/gravity-scorer.js` existed but was orphaned (never imported)
- MMR entity dedup kept highest-relevance item, not newest
- Injection builder sorted by similarity only — no chronological ordering
- LLM directives said nothing about preferring recent info

### Layered Fix (3 files)

**Layer 1: Mild recency multiplier on all search results** (`background.js`)
- Applied immediately after search results return, before any post-processing
- Exponential decay: 15% weight, 30-day half-life
- `score = score * 0.85 + score * exp(-days/30) * 0.15`
- Helps newer memories compete with semantically richer older ones during MMR

**Layer 2: Entity-aware contradiction resolution** (`background.js`)
- New `applyRecencyResolution()` function, inserted after content dedup and before MMR
- Groups items by shared entities (via `extractEntities()` from mmr.js)
- When newest item contains negation signals (not, isn't, don't, fake, wrong, etc.): 1.5x boost + 0.6x penalty on older items
- Without negation: mild 1.15x recency boost on newest item per entity
- Imported `extractEntities` from `src/mmr.js` (added `export` keyword)

**Layer 3: Recency directive + chronological sort in injection builder** (`kyt-memory-injection-builder.js`)
- Items sorted newest-first (by timestamp) instead of by similarity
- High-confidence tier: Rule 10 — "MOST RECENT item reflects current knowledge"
- Medium-confidence tier: Rule 5 — "prefer the most recent one"
- LLM sees newest item first + explicit instruction to prefer it when conflicts exist

### Files Modified
| File | Change | Risk |
|------|--------|------|
| `kyt-memory-injection-builder.js` | Chronological sort + recency directives | Low — presentation-only |
| `background.js` | Recency multiplier + entity-aware contradiction resolution + `extractEntities` import | Medium — affects scoring |
| `src/mmr.js` | Export `extractEntities` (add `export` keyword) | Low — no behavior change |

### Pipeline Order (post-search)
1. Mild recency multiplier (15% weight) → 2. Recursion guard → 3. Meta filter → 4. Deflection penalty → 5. Meta/Echo penalties → 6. Content dedup → 7. **Entity-aware recency resolution** → 8. MMR → 9. Keyword boost → 10. Confidence filter → 11. Injection builder (newest-first sort)

## ✅ Advanced GraphRAG Implementation (2026-02-14)

### Problem: Concept Labeling Gap
User remembers "the walking analogy" but stored text says "you don't tell a child who took 4 steps to scratch everything." Embedding models cannot bridge this gap — it's a concept labeling problem. GraphRAG is the solution: GPT-4o-mini labels concepts at ingest, graph walk retrieves by label at query time.

### Phase 0: Bug Fixes
- **0A: entities_extracted flag** — `save_chat_turn/index.ts` + `save_chat_turn_batch/index.ts`: After `saveEntitiesWithMentions()` succeeds, sets `chat_turns.entities_extracted = true`. Without this, backfill can't know which turns already had extraction.
- **0B: Vector dimension mismatch** — Migration `20260216000000`: `find_similar_entities` RPC changed from `VECTOR(1536)` to `VECTOR(4096)` (Qwen3-Embedding-8B). Entity resolution depends on this.

### Phase 1: Text-Based Entity Search Fallback
- Migration `20260216000001`: Enables `pg_trgm` extension, creates GIN trigram indexes on `entities.canonical_name/normalized_name/entity_text`, adds `search_entities_by_text()` RPC with 3 strategies (trigram similarity, ILIKE substring, keyword splitting).
- `get_relevant_memories.ts`: `searchEntities()` falls back to text search when embedding search returns 0.
- `browser-search.js`: `searchGraphWalk()` adds text entity search fallback client-side.

### Phase 2+3: Multi-Hop Graph Walk + Temporal Decay
- Migration `20260216000002`: `temporal_decay_factor()` helper (half-life 90 days). Recursive `graph_walk_from_entities()` with `p_max_depth` and `p_max_intermediate` params. Cumulative strength = product of edge strengths × temporal decay.
- Both server and client integration pass `p_max_depth: 2, p_max_intermediate: 20`.

### Phase 4: Relationship Classification
- Migration `20260216000003`: Adds `relationship_type` column to `entity_relationships` + index. Updates `upsert_entity_relationship` with 4th param; "keep more-specific type" conflict logic.
- `entity-extractor.ts`: New `classifyRelationshipType()` derives type from entity metadata (family_of, works_with, illustrates, discussed_together, co_occurrence).

### Phase 5: Entity Resolution (Fuzzy Dedup)
- `entity-extractor.ts`: After exact canonical_name match fails, calls `find_similar_entities()` (4096-dim). Merges only if same `entity_type` + same relationship suffix + similarity >= 0.90. Prevents "Jenn"/"Jennifer_trainer" duplication while keeping "Jennifer_trainer"/"Jennifer_sister" distinct.

### Phase 6: Query-Time Concept Detection
- `get_relevant_memories.ts`: New `detectConceptEntities()` uses text search to find CONCEPT/ANALOGY/THEME entities. Runs in parallel with entity search + HyDE. Concept entity IDs merged into `boostEntityIds` for graph walk.

### Phase 7: Entity Re-Extraction Backfill
- New edge function `backfill_entities/index.ts`: Queries `entities_extracted = false`, runs `extractEntities()` + `saveEntitiesWithMentions()` per row. Batch size 5, max 100/invocation, 2s delay between batches.
- `background.js`: Added `KYT_DEBUG.backfillEntities()` debug command.

## Previous Work: Claude Bridge Queue-Manager Resilience (2026-02-11)

### Claude Bridge: Queue-Manager Integration - COMPLETE
- **Problem**: After extension reload, `content_bridge.js` drops captured messages silently
  when `chrome.runtime.id` becomes undefined (context invalidation). ChatGPT platform
  already handled this via `queue-manager.js`; Claude bridge had no fallback.
- **Fix**: Static import of queue-manager into `platforms/claude/content_bridge.js`
  with module content script (`"type": "module"` in manifest).
- **CSP fix**: Initial dynamic `import()` failed on claude.ai because classic content
  scripts route module fetches through the host page's CSP, which blocks
  `chrome-extension://` origins. Switching to `"type": "module"` makes Chrome resolve
  imports at injection time via the extension's own loader, bypassing page CSP.
- **Simplification**: Since `queueManager` is always available via static import,
  the handler is now a single `queueManager.capture(messageData)` call. The queue
  manager handles the full fallback chain internally:
  1. `chrome.runtime.sendMessage` to background (context valid)
  2. Encrypted `chrome.storage.local` (context invalid, crypto key available)
  3. Unencrypted `chrome.storage.local` (no crypto key)
  4. `window.localStorage` emergency fallback (chrome.storage unavailable)
- **Recovery**: `background.js:processPendingLocalQueues()` already processes pending
  queues on startup, install, and alarm — no background changes needed.
- Files: `platforms/claude/content_bridge.js`, `manifest.json`
- Tests: 215 passed, 5 skipped, 3 pre-existing failures (embedding dimension + dedup flake in history-import.spec.js)
